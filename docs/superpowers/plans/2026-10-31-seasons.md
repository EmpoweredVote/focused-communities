# Seasons Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let any visitor view a Focused Community as it stood in any Compass season, and read why it changed.

**Architecture:** Three `SECURITY DEFINER` RPCs in the `connect` schema expose `inform.*` season data to the engine's narrowly-scoped `focused_communities_app` role, which has no grant on `inform` at all. A new `routes/seasons.ts` in the engine serves them under `/fc/api`. The frontend gains a season selector governing bands 1–2 only; bands 3–4 are untouched. Chair position integers never leave the API — ladder order is carried by array order.

**Tech Stack:** PostgreSQL (Supabase, shared instance), Express/TypeScript in `EmpoweredVote/ev-accounts`, vitest + supertest for the engine, Vite/React/TypeScript + Tailwind v4 in `EmpoweredVote/focused-communities`, vitest + React Testing Library (added in Task 5).

**Spec:** `docs/superpowers/specs/2026-10-30-seasons-and-argument-tree-design.md`

## Global Constraints

- **Two repos.** Migrations and API: `EmpoweredVote/ev-accounts`, under `backend/`. UI: this repo, under `frontend/`. The backend in this repo's `src/` is frozen — never modify it.
- **Never expose stance position integers.** No `value`, no `position`, no 1–5 in any response body or component. Ladder order is array order.
- **The `focused_communities_app` role has no `inform` access and no BYPASSRLS.** Every new read is a `SECURITY DEFINER` RPC in `connect` plus an explicit `GRANT EXECUTE`. Follow `CA_0323_focused_communities_scoped_role.sql`.
- **Timestamps use `ts()` from `lib/sql.ts`** (`to_json(col) #>> '{}'`). A JS `Date` truncates to milliseconds and breaks cursors.
- **Open season reads `inform.compass_stances`; historical seasons read `inform.compass_stance_revisions`.** Open-season revision rows are 75/300 authored.
- **Draft seasons are Maven/Admin only.** Use the engine's `requireRole('maven')` from `backend/src/middleware/requireRole.ts`. No env allowlist.
- **Never invent data in a component.** Anything unserved goes in `frontend/src/mocks/` headed `// Stands in for: GET /api/<route> — not yet served by the API`.
- **Use `@empoweredvote/ev-ui` components** rather than copying or restyling them.
- Cache keys keep the `fc:` prefix. Auth-touching responses carry `Cache-Control: private, no-store`.
- Response envelopes: list → `{ data, meta }`, single → `{ data }`.

## Review Focus

1. **A community absent from the requested season.** `immigration-and-treatment` has no Season 2 row and 16 topics have no Season 1 row — must fall back to that topic's latest available season, not 500 or render an empty ladder. *(Task 3)*
2. **A season whose chairs have `description = null`.** 225 of 300 open-season rows and 40 of 220 Season 1 rows. Band 2 must render chair text without the deep dive, never "null" or a blank card. *(Tasks 3, 8)*
3. **A draft season requested by a non-Maven.** Must behave exactly as if the season does not exist — absent from the list, 404 on direct request — never a 403, which would confirm it exists. *(Tasks 2, 3)*
4. **`rung_map` that is null, many-to-one, or carries the `"invalidated"` string sentinel.** 66 of 147 revisions have no map; 2 contain a sentinel. The per-chair marker must be suppressed, not crash on a string where an integer is expected. *(Task 9)*
5. **A malformed `?season=` parameter** — non-numeric, negative, or a season that exists platform-wide but not for this topic. Must resolve to the default season, not 500. *(Tasks 3, 6)*

### Task 1: Season RPCs and grants

**Files:**
- Create: `backend/migrations/CA_0340_focused_communities_seasons.sql`

**Interfaces:**
- Consumes: the `focused_communities_app` role created by `CA_0323`.
- Produces: three functions callable by that role —
  - `connect.get_season_list(p_topic_id uuid, p_include_drafts boolean)` → `TABLE(season_number int, season_name text, status text, opened_at text, closed_at text)`, ordered by `season_number`.
  - `connect.get_season_detail(p_topic_id uuid, p_season_number int, p_include_drafts boolean)` → `TABLE(season_number int, season_name text, status text, question_text text, change_class text, season_note text, topic_note text, rationale text, rung_map jsonb)`, zero rows if absent or draft-and-not-permitted.
  - `connect.get_season_chairs(p_topic_id uuid, p_season_number int)` → `TABLE(ordinal int, text text, description text, supporting_points text[], example_perspectives text[])`, ordered by the underlying `value` ascending, with `ordinal` a 1-based row number used only for joining to `rung_map` server-side.

- [ ] **Step 1: Write the migration**

Three `CREATE OR REPLACE FUNCTION ... SECURITY DEFINER` definitions joining `inform.season_questions` → `inform.seasons` → `inform.compass_topic_revisions` (and `inform.compass_stance_revisions` for chairs), each filtering `seasons.status <> 'draft'` unless `p_include_drafts`. Timestamps are returned as text via `to_json(col) #>> '{}'`. End with `GRANT EXECUTE ON FUNCTION ... TO focused_communities_app;` for all three, and `REVOKE ALL ... FROM PUBLIC`.

- [ ] **Step 2: Apply it against the shared instance**

Use the Supabase MCP `apply_migration`, never `db push`.

- [ ] **Step 3: Verify the role can call them and still cannot read `inform` directly**

Run as `focused_communities_app`:
```sql
SELECT * FROM connect.get_season_list('<abortion topic_id>', false);
SELECT * FROM inform.seasons;
```
Expected: the first returns Seasons 1 and 2 and omits draft Season 3; the second fails with `permission denied for schema inform`.

- [ ] **Step 4: Commit**

```bash
git add backend/migrations/CA_0340_focused_communities_seasons.sql
git commit -m "feat(fc): season RPCs and grants for the scoped role (CA_0340)"
```
