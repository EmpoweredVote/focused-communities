## Things that bit, so they do not bite again

**Both repos are squash-only.** No merge commits, no rebase merges. A stacked PR therefore breaks
the moment its base merges: GitHub retargets it to master, and the branch still carries the base's
original commits, so the diff doubles and conflicts. The fix each time was
`git rebase --onto origin/master <old-base-tip> <branch>` then `--force-with-lease`. Keep a local
backup branch first. Branching each new PR from `origin/master` instead sidesteps it entirely.

**Migration slots must be reserved through the steward, and it needs credentials.**
`node scripts/steward.mjs slot CA --purpose "..."` — run it from **`C:\EV-Accounts\backend`**,
which is the only checkout with a `DATABASE_URL`. From a worktree without one it prints
`DATABASE_URL is not set` and **exits 0**, which looks like success. Highest reserved slot is
**CA_0347**.

**The frontend lockfile cannot be regenerated on this Windows machine.** npm prunes optional
native packages that do not apply to the current platform, so the `@emnapi` entries bundled in
`@tailwindcss/oxide-wasm32-wasi` disappear and Linux CI's `npm ci` fails. Four approaches were
tried, including `--os=linux --cpu=x64`; all prune. There is no WSL distro or Docker. **If you
touch `frontend/package.json`, the lockfile must be regenerated on Linux** — the pattern that
worked was a temporary GitHub Actions workflow that regenerates it, proves it by running `npm ci`
and `npm run build` against the result, and only then commits. It was deleted after use; the
commit that added it is `dc48bd9` on the seasons branch if you want the shape.

**`npm ci` is safe; `npm install` is the one to avoid.** The warning above is about regenerating
the lockfile. `npm ci` only installs *from* it and writes nothing — verified with `git status` on
`package-lock.json` straight afterwards. It is the right way to pick up merged Dependabot bumps
locally.

**A killed dev server can leave a live child.** Stopping a backgrounded `npx vite` kills the
wrapper, not the `vite` process under it. The orphan holds a lock on
`node_modules/lightningcss-win32-x64-msvc/lightningcss.win32-x64-msvc.node`, and the next
`npm ci` dies with `EPERM: operation not permitted, unlink`. Check for stray node processes and
kill the ones that are yours — this machine also runs Civic Spaces dev servers and MCP servers
that must be left alone.

**CI only runs on PRs targeting `master`** in focused-communities, so a stacked PR shows no checks
at all. An empty check list is not a passing one. And a build triggered by a bot commit sits at
`action_required` until approved.

**ev-accounts CI is the org's Actions bill.** The workflow file says so at the top, in detail. Do
not re-run jobs idly.

**`index.contrast.test.ts` parses `index.css` with a regex that does not know what a comment is.**
It harvests `--color-x: value;` from the whole file, prose included, so a comment that writes a
token name followed by a colon and a sentence is read as a declaration and fails the hex check.
Write `--color-ev-coral-hover —` rather than `--color-ev-coral-hover:` inside a comment. It fails
as a confusing resolution error rather than as anything about contrast.

## Still open

From the rulings file, unchanged:

- Task 5's aggregate records `rater_account_age_days` and `rater_verification_status` but ignores
  them. Weighting them is a product decision nobody has made.
- A narrow hidden-ancestor race at write time, owned by hide, documented where it happens.
- `GET /claims/:claimId/edits` is built, typed and tested with **no UI consumer**.
- `CA_0323` carries the same OR-not-AND `has_table_privilege` bug that CA_0342 fixed locally.
- `service_role` retains `TRIGGER` on `claim_edits`, schema-wide.
- A rating inside its 400 ms debounce is lost on a back button or a closed tab.
- "Immigration & Treatment of Immigrants" has a community whose topic appears only in the closed
  Season 1, so its page shows a single past season with no explanation.

Raised by the work above and deliberately not done:

- **`ImpactControl` ignores its `mergedInto`.** The rating route sends it so a rating can be
  re-aimed at the claim readers will actually meet, which is the same courtesy #77 built for the
  composer. Offering to re-aim a rating is a different question from offering to re-home an
  argument, and nobody has asked it.
- **Dark mode draws no muted/secondary distinction.** `--color-text-muted` (`#7DD4E8`) and
  `--color-text-secondary` (`#A7CFD8`) sit at the same luminance — 1.01:1 — and differ only in
  hue, so the hierarchy #76 restored in light mode has no counterpart. Both clear AA, so this is a
  design decision rather than a contrast one. `index.contrast.test.ts` records it.
- **A merge chain is declined rather than walked.** If a merged parent's destination has itself
  been merged, #77 makes no offer, because the tree renders no composer on a merged claim and the
  draft would land somewhere with no box to appear in. Walking the chain to its end is the richer
  answer. Chains are bounded by the API (`MERGE_CHAIN_TOO_LONG`), not forbidden.
- **CLAUDE.md's two stale claims**, above.
