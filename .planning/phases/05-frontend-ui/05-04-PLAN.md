    **useCreateThread (frontend/src/hooks/useCreateThread.ts):**
    Create a mutation hook using `useMutation` from `@tanstack/react-query`.

    - Parameters: `(communityId: string, communitySlug: string)`
    - mutationFn: `async ({ title, body }: { title: string; body: string })` — calls `apiFetch<{ data: Thread }>` with `POST /api/communities/${communityId}/threads` and `JSON.stringify({ title, body })`.
    - On success: Use `navigate` from `react-router` (the hook must accept or use `useNavigate` internally) to redirect to `/communities/${communitySlug}/threads/${data.data.id}`. Also invalidate the threads query: `queryClient.invalidateQueries({ queryKey: ['threads', communityId] })`.
    - On error: Handle different status codes from the `apiFetch` result:
      - If the mutationFn receives a non-ok result, it should throw an error that includes the status and reason.
      - `status === 429`: `toast.error('Too many posts. Please wait a few minutes.')`
      - `status === 403` with `reason === 'suspended'`: Set a local `suspended` state that the form component can read to show `<SuspendedNotice />`
      - `status === 422`: `toast.error('Please check your input and try again.')`
      - Other errors: `toast.error("Couldn't create thread. Try again.")`
    - Import `toast` from `sonner`.
    - Return the mutation object plus any `suspended` state flag.

    **useCreateReply (frontend/src/hooks/useCreateReply.ts):**
    Create a mutation hook using `useMutation` with optimistic updates.

    Follow the exact pattern from 05-RESEARCH.md Pattern 5:

    - Parameters: `(threadId: string)`
    - mutationFn: `async (body: string)` — calls `apiFetch<{ data: Post }>` with `POST /api/threads/${threadId}/posts` and `JSON.stringify({ body })`. If `!result.ok`, throw an error with status and reason.
    - `onMutate`:
      1. `await queryClient.cancelQueries({ queryKey: ['posts', threadId] })`
      2. Save previous: `queryClient.getQueryData(['posts', threadId])`
      3. Optimistically add: `queryClient.setQueryData(['posts', threadId], (old) => ({ data: [...(old?.data ?? []), { id: 'optimistic-' + Date.now(), body: bodyParam, authorPseudonym: '...', createdAt: new Date().toISOString(), updatedAt: new Date().toISOString(), isEdited: false }] }))` — note the response shape is `{ data: Post[] }`, so wrap accordingly.
      4. Return `{ previous }`
    - `onError`: Roll back with `queryClient.setQueryData(['posts', threadId], context?.previous)`. Then:
      - `status === 429`: `toast.error('Too many posts. Please wait a few minutes.')`
      - `status === 403` with `reason === 'suspended'`: return the suspended flag (similar to thread hook)
      - Default: `toast.error("Couldn't post. Try again.")`
    - `onSettled`: `queryClient.invalidateQueries({ queryKey: ['posts', threadId] })` — ensures optimistic data is replaced with real server data.
    - Also invalidate thread detail to update reply count: `queryClient.invalidateQueries({ queryKey: ['thread', threadId] })`
