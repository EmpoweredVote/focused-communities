**Route 1: GET /threads/:id (thread detail)**

Apply `cacheMiddleware(TTL.THREAD_DETAIL)` — 30-second cache.

Returns the full thread object including the complete body (raw markdown — frontend renders it).

```typescript
import { Router } from 'express';
import type { Request, Response } from 'express';
import { supabase } from '../lib/supabase.js';
import { cacheMiddleware, TTL } from '../middleware/cache.js';
import { parseLimit } from '../lib/utils.js';

export const postsRouter = Router();

postsRouter.get('/threads/:id', cacheMiddleware(TTL.THREAD_DETAIL), async (req: Request, res: Response) => {
  const { data, error } = await supabase
    .schema('connect')
    .from('threads')
    .select('id, title, body, author_display_name, reply_count, created_at, last_activity_at, moderation_status')
    .eq('id', req.params.id)
    .single();

  if (error || !data) {
    res.status(404).json({
      error: { code: 'THREAD_NOT_FOUND', message: 'Thread not found' },
    });
    return;
  }

  // Hidden threads are not accessible via public API
  if (data.moderation_status !== 'visible') {
    res.status(404).json({
      error: { code: 'THREAD_NOT_FOUND', message: 'Thread not found' },
    });
    return;
  }

  res.json({
    data: {
      id: data.id,
      title: data.title,
      body: data.body,
      authorPseudonym: data.author_display_name,
      replyCount: data.reply_count,
      createdAt: data.created_at,
      lastActivityAt: data.last_activity_at,
    },
  });
});
```

Key details:
- Select `moderation_status` to check visibility, but do NOT include it in the response — the check is server-side only
- Hidden threads return 404 (not 403) — do not reveal that the thread exists but is hidden
- `body` is the full raw markdown — NOT an excerpt. Thread detail shows the complete content.
- `.single()` returns error on zero or multiple rows — treat as 404

**Route 2: GET /threads/:id/posts (flat chronological replies)**

Apply `cacheMiddleware(TTL.THREAD_DETAIL)` — same 30-second TTL as thread detail.

Query parameters:
- `?limit=` (number, optional, default: 50, max: 100) — per CONTEXT.md, posts default to 50

Returns ALL visible posts for the thread ordered by `created_at ASC` (flat, chronological). Per REPL-01, "flat" means no tree structure in the response — return all posts regardless of `parent_post_id` nesting depth.

```typescript
postsRouter.get('/threads/:id/posts', cacheMiddleware(TTL.THREAD_DETAIL), async (req: Request, res: Response) => {
  const threadId = req.params.id;
  const limit = parseLimit(req.query.limit as string | undefined, 50);

  // Verify thread exists and is visible
  const { data: thread, error: threadError } = await supabase
    .schema('connect')
    .from('threads')
    .select('id, moderation_status')
    .eq('id', threadId)
    .single();

  if (threadError || !thread || thread.moderation_status !== 'visible') {
    res.status(404).json({
      error: { code: 'THREAD_NOT_FOUND', message: 'Thread not found' },
    });
    return;
  }

  // Fetch all visible posts for this thread, flat chronological order
  const { data, error } = await supabase
    .schema('connect')
    .from('posts')
    .select('id, author_display_name, body, created_at, updated_at')
    .eq('thread_id', threadId)
    .eq('moderation_status', 'visible')
    .order('created_at', { ascending: true })
    .limit(limit);

  if (error) {
    res.status(500).json({
      error: { code: 'POSTS_FETCH_FAILED', message: error.message },
    });
    return;
  }

  const posts = (data ?? []).map(p => ({
    id: p.id,
    authorPseudonym: p.author_display_name,
    body: p.body,
    createdAt: p.created_at,
    updatedAt: p.updated_at,
  }));

  res.json({ data: posts });
});
```

Key details:
- Thread existence check first — return 404 if thread doesn't exist or is hidden. This prevents leaking post data for hidden threads.
- No cursor pagination for posts — CONTEXT.md says default limit 50 (up to max 100). For v1, flat list with a limit is sufficient. If a thread has >100 posts, cursor pagination can be added in a future enhancement.
- `moderation_status = 'visible'` on the posts query filters out hidden posts
- No `parent_post_id` filter — "flat" per REPL-01 means all posts regardless of nesting
- `created_at ASC` order — chronological (oldest first) per REPL-01
- `body` is raw markdown — same as thread detail
- `updatedAt` included per REPL-03 — frontend can show "edited" indicator if `updatedAt > createdAt`
- Response is `{ data: [...] }` without `meta` — no cursor pagination for posts in v1. This matches the CONTEXT.md single-resource pattern for flat lists without pagination metadata.

IMPORTANT: Do NOT add `parent_post_id` to the response. The "flat" display means the client does not render a tree. If nested reply UI is added later (Phase 5+), the API can return `parentPostId` then. For now, keep the response shape minimal.
