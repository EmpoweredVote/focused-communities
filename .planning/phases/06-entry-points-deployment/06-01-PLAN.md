  <name>Task 1: GET /api/users/:id/posts endpoint + route registration</name>
  <files>src/routes/users.ts, src/app.ts</files>
  <action>
Create `src/routes/users.ts` exporting `usersRouter` with a single route: `GET /users/:id/posts`.

Follow the exact cursor-pagination pattern from `src/routes/threads.ts`:

1. **Auth + self-only gate**: Use `requireAuth` middleware. Check `req.params.id !== req.user!.id` and return 403 with `{ error: { code: 'FORBIDDEN', message: 'You can only view your own post history' } }` if mismatch. Do NOT use `requireConnected` — the endpoint only checks identity match.

2. **Query**: Use `supabase.schema('connect').from('posts').select(...)` with nested `!inner` joins:
   ```
   id, body, author_display_name, created_at, updated_at,
   thread:threads!inner(id, title, community_id, community:communities!inner(id, name, slug))
   ```
   Filter: `.eq('author_id', req.user!.id)` and `.eq('moderation_status', 'visible')`.
   Order: `.order('created_at', { ascending: false }).order('id', { ascending: false })`.
   Do NOT filter on `thread.moderation_status` in the top-level Supabase filter chain — rely on the `!inner` join to exclude posts whose thread/community row doesn't exist. This avoids PostgREST nested filter syntax issues (see RESEARCH.md Pitfall 1).

3. **Cursor pagination**: Use `decodeCursor`/`encodeCursor` from `src/lib/utils.ts`. Apply the `.or()` filter for cursor the same way threads.ts does: `created_at.lt.${decoded.t},and(created_at.eq.${decoded.t},id.lt.${decoded.id})`. Use `parseLimit(req.query.limit, 20)` for default page size of 20.

4. **Response mapping**: Map each post to:
   ```typescript
   {
     postId: p.id,
     threadId: (p.thread as any).id,
     threadTitle: (p.thread as any).title,
     communityId: (p.thread as any).community_id,
     communityName: (p.thread as any).community.name,
     communitySlug: (p.thread as any).community.slug,
     postExcerpt: generateExcerpt(p.body, 200),
     createdAt: p.created_at,
     isEdited: p.updated_at !== p.created_at,
     authorPseudonym: p.author_display_name,
   }
   ```
   Use `(p.thread as any)` for nested join fields — the codebase uses this pattern for Supabase nested selects.

5. **Response envelope**: `{ data: items, meta: { cursor: nextCursor, hasMore } }` matching all other list endpoints.

6. **Error handling**: Return 500 with `{ error: { code: 'POST_HISTORY_FETCH_FAILED', message: error.message } }` on query failure.

7. **CRITICAL: Do NOT apply `cacheMiddleware`** — this is an auth-gated, user-specific endpoint. Caching would serve one user's data to another (see RESEARCH.md Pitfall 2).

Register in `src/app.ts`: Import `usersRouter` from `./routes/users.js` and add `app.use('/api', usersRouter)` alongside the other routers.

  <action>
Create `.planning/phases/06-entry-points-deployment/ACCOUNTS-HANDOFF-SPEC.md` — a handoff document for the Accounts team.

Structure:

1. **Overview**: FC provides a post history API; Accounts owns the profile page UI.

2. **Base URLs**: 
   - Production: `https://fc.empowered.vote`
   - Temporary: `https://focused-communities.onrender.com`

3. **Endpoint**: `GET /api/users/:id/posts`
   - Method: GET
   - Auth: Bearer token (Supabase JWT) in Authorization header
   - Access: Self-only — `:id` must match the authenticated user's JWT `sub` claim. Returns 403 for mismatch, 401 for missing/invalid token.
   - Future: When Empower public profiles launch, the endpoint URL stays the same — just the auth gate relaxes.

4. **Request parameters**:
   - `cursor` (query, optional): Pagination cursor from previous response's `meta.cursor`
   - `limit` (query, optional): Page size, default 20, max 100

5. **Response schema**: Full JSON schema for `{ data: PostHistoryItem[], meta: { cursor: string | null, hasMore: boolean } }` with field definitions:
   - `postId` (string, UUID)
   - `threadId` (string, UUID)
   - `threadTitle` (string)
   - `communityId` (string, UUID)
   - `communityName` (string)
   - `communitySlug` (string)
   - `postExcerpt` (string, first ~200 chars, plain text with ellipsis)
   - `createdAt` (string, ISO 8601)
   - `isEdited` (boolean)
   - `authorPseudonym` (string) — the display name snapshotted at post time

6. **Display requirements**:
   - Always show `authorPseudonym` — NEVER the user's legal name
   - Thread link construction: `https://fc.empowered.vote/communities/{communitySlug}/threads/{threadId}`
   - Show `communityName` as context per row
   - Show `isEdited` indicator (e.g., "(edited)" badge)
   - Sort: newest first (API returns in this order)

7. **Pagination instructions**: Fetch first page with no cursor. If `meta.hasMore` is true, pass `meta.cursor` as `?cursor=` on next request. Continue until `hasMore` is false.

8. **Error responses**: 401 (missing/invalid token), 403 (not own history), 500 (server error).

9. **Cross-product aggregation vision**: FC is the first product implementing the EV Post History Standard. In future, Accounts aggregates post history from FC + Civic Spaces + other products. Each product serves its own `/api/users/:id/posts` endpoint; Accounts fans out requests and merges by `createdAt`.
