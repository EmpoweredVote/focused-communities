Create `.planning/phases/06-entry-points-deployment/EV-POST-HISTORY-STANDARD.md` — the cross-product API contract that every EV product should implement so Accounts can aggregate post history.

This is the most important document in Plan 02. It defines a standard, not just FC's implementation.

**Structure:**

1. **Purpose**: Enable Accounts to aggregate user post history across all EV products (Focused Communities, Civic Spaces, future products) into a unified timeline. Each product implements this standard; Accounts fans out requests and merges results.

2. **API Contract**:
   - Endpoint path: `GET /api/users/:id/posts` (every product uses the same path)
   - Auth: Bearer JWT (Supabase) in Authorization header
   - Access model: Self-only for Connect accounts (`:id` must match JWT `sub`); publicly browsable for Empower accounts (future). Each product decides its own access policy.
   - Pagination: cursor-based via `?cursor=` and `?limit=` query parameters
   - Response envelope: `{ data: PostHistoryItem[], meta: { cursor: string | null, hasMore: boolean } }`

3. **Required response fields per post**:
   | Field | Type | Description |
   |-------|------|-------------|
   | `postId` | string (UUID) | Unique post identifier within this product |
   | `sourceProduct` | string | Product identifier, e.g. `"focused-communities"`, `"civic-spaces"` |
   | `threadId` | string (UUID) | Thread or context identifier |
   | `threadTitle` | string | Human-readable thread/context title |
   | `communityId` | string (UUID) | Community or space identifier |
   | `communityName` | string | Human-readable community/space name |
   | `postExcerpt` | string | Plain text, first ~200 chars, word-boundary truncated with ellipsis |
   | `createdAt` | string (ISO 8601) | When the post was created |
   | `isEdited` | boolean | Whether the post has been edited |
   | `authorPseudonym` | string | Display name snapshotted at post time |

   Optional fields (product-specific):
   | Field | Type | Description |
   |-------|------|-------------|
   | `communitySlug` | string | URL-safe slug for link construction |
   | `postUrl` | string | Direct URL to the post in its product |

4. **Pseudonym rules**:
   - NEVER expose legal name in post history
   - Use the pseudonym that was active when the post was created (snapshotted, not live)
   - If a user changes their display name, old posts retain their original pseudonym

5. **Pagination contract**:
   - First page: `GET /api/users/:id/posts` (no cursor)
   - Next page: `GET /api/users/:id/posts?cursor={meta.cursor}`
   - Custom page size: `?limit=N` (default 20, max 100)
   - Stop when `meta.hasMore === false`
   - Cursor format is opaque — consumers must not parse it

6. **Error responses**:
   - 401: Missing or invalid token
   - 403: Not authorized to view this user's history
   - 500: Server error

7. **Accounts aggregation pattern** (informational):
   - Accounts sends parallel requests to each registered product's `/api/users/:id/posts`
   - Merges responses by `createdAt` (newest first)
   - Uses `sourceProduct` field to label each post's origin
   - Link construction: Uses `postUrl` if provided, or product-specific URL templates

8. **FC reference implementation**:
   - Base URL: `https://fc.empowered.vote`
   - `sourceProduct`: `"focused-communities"`
   - Thread link: `https://fc.empowered.vote/communities/{communitySlug}/threads/{threadId}`
   - Implementation: `src/routes/users.ts` — cursor-paginated Supabase query joining posts -> threads -> communities

9. **Civic Spaces implementation guide**:
   - Civic Spaces does not currently have a post history endpoint
   - To adopt the standard: Create `GET /api/users/:id/posts` returning the required fields above
   - `sourceProduct`: `"civic-spaces"`
   - Map Civic Spaces' existing data model to the standard fields (thread/community equivalents)
   - Pseudonym snapshotting may require a schema addition if not already present
