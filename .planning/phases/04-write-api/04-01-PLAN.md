       - Export `postRateLimiter: Ratelimit`

<task type="auto">
  <name>Task 2: POST /api/communities/:id/threads and POST /api/threads/:id/posts</name>
  <files>
    src/routes/threads.ts
    src/routes/posts.ts
  </files>
  <action>
    **POST /api/communities/:id/threads** — Add to `src/routes/threads.ts`:

    1. Add imports: `requireAuth` from `../middleware/auth.js`, `requireConnected` from `../middleware/tierGuards.js`, `postRateLimiter` from `../lib/rateLimit.js`, `cacheDel` from `../lib/redis.js`
    2. Add route: `threadsRouter.post('/communities/:id/threads', requireAuth, requireConnected, async (req, res) => { ... })`
    3. Validation — extract `title` and `body` from `req.body`:
       - `const trimmedTitle = (title ?? '').trim()` — if length < 5 or > 150: `errors.title = 'Title must be 5-150 characters'`
       - `const trimmedBody = (body ?? '').trim()` — if length < 10 or > 5000: `errors.body = 'Body must be 10-5,000 characters'`
       - If any errors: return `422` with `{ errors }` (field-level error object)
    4. Rate limiting:
       - `const { success, reset } = await postRateLimiter.limit(req.user!.id)`
       - If `!success`: set `Retry-After` header to `Math.ceil((reset - Date.now()) / 1000)`, return `429` with `{ reason: 'rate_limited' }`
       - IMPORTANT: `reset` from @upstash/ratelimit is milliseconds — divide by 1000 for seconds
    5. Insert via supabase service role:
       ```typescript
       const { data, error } = await supabase
         .schema('connect')
         .from('threads')
         .insert({
           community_id: req.params.id,
           author_id: req.user!.id,
           title: trimmedTitle,
           body: trimmedBody,
         })
         .select('id, title, body, author_display_name, reply_count, created_at, last_activity_at, updated_at')
         .single();
       ```
       - The DB trigger `trg_threads_snapshot_display_name` fires BEFORE INSERT and populates `author_display_name` automatically
       - If error or !data: return `500` with `{ error: { code: 'THREAD_CREATE_FAILED', message: error?.message } }`
    6. Cache invalidation — invalidate the thread list cache for this community:
       ```typescript
       await cacheDel(`fc:/api/communities/${req.params.id}/threads:${JSON.stringify({})}`);
       ```
       - Only invalidate the base key (no query params). Parameterized variants expire via 30s TTL — acceptable for v1.
    7. Return `201` with camelCase response envelope:
       ```typescript
       res.status(201).json({
         data: {
           id: data.id,
           title: data.title,
           body: data.body,
           authorPseudonym: data.author_display_name,
           replyCount: data.reply_count,
           createdAt: data.created_at,
           lastActivityAt: data.last_activity_at,
           updatedAt: data.updated_at,
           isEdited: false,
         },
       });
       ```

    **POST /api/threads/:id/posts** — Add to `src/routes/posts.ts`:

    1. Add imports: `requireAuth` from `../middleware/auth.js`, `requireConnected` from `../middleware/tierGuards.js`, `postRateLimiter` from `../lib/rateLimit.js`, `cacheDel` from `../lib/redis.js`
    2. Add route: `postsRouter.post('/threads/:id/posts', requireAuth, requireConnected, async (req, res) => { ... })`
    3. Verify thread exists and is visible:
       ```typescript
       const { data: thread, error: threadError } = await supabase
         .schema('connect')
         .from('threads')
         .select('id, moderation_status, reply_count')
         .eq('id', req.params.id)
         .single();
       ```
       - If threadError or !thread or thread.moderation_status !== 'visible': return `404` with `{ error: { code: 'THREAD_NOT_FOUND', message: 'Thread not found' } }`
    4. Validation — extract `body` from `req.body`:
       - `const trimmedBody = (body ?? '').trim()` — if length < 10 or > 5000: `errors.body = 'Body must be 10-5,000 characters'`
       - If errors: return `422` with `{ errors }`
    5. Rate limiting — same shared bucket as thread creation:
       - `const { success, reset } = await postRateLimiter.limit(req.user!.id)`
       - If `!success`: `Retry-After` header + `429` with `{ reason: 'rate_limited' }`
    6. Insert post:
       ```typescript
       const { data, error } = await supabase
         .schema('connect')
         .from('posts')
         .insert({
           thread_id: req.params.id,
           author_id: req.user!.id,
           body: trimmedBody,
         })
         .select('id, body, author_display_name, created_at, updated_at')
         .single();
       ```
       - DB trigger handles display name snapshot
       - If error or !data: return `500`
    7. Update thread's reply_count and last_activity_at — NO trigger exists for this, must do in application code:
       ```typescript
       await supabase
         .schema('connect')
         .from('threads')
         .update({
           reply_count: thread.reply_count + 1,
           last_activity_at: new Date().toISOString(),
         })
         .eq('id', req.params.id);
       ```
       NOTE: This is NOT atomic with the insert. For v1, the race condition on reply_count is acceptable (low concurrency). Fire-and-forget is fine — don't block the response on this update.
    8. Cache invalidation — invalidate thread detail AND thread list AND posts list:
       ```typescript
       await cacheDel(
         `fc:/api/threads/${req.params.id}:${JSON.stringify({})}`,
         `fc:/api/threads/${req.params.id}/posts:${JSON.stringify({})}`,
       );
       ```
       - Thread list cache for the community would also be stale (reply_count changed), but we don't have community_id readily available without another query. The 30s TTL handles this.
    9. Return `201` with camelCase response:
       ```typescript
       res.status(201).json({
         data: {
           id: data.id,
           body: data.body,
           authorPseudonym: data.author_display_name,
           createdAt: data.created_at,
           updatedAt: data.updated_at,
           isEdited: false,
         },
       });
       ```

    IMPORTANT: Both routes use `requireAuth, requireConnected` middleware chain — same pattern as discussed in Phase 2 auth infrastructure.
    IMPORTANT: Do NOT add `express.json()` middleware — it's already applied globally in `app.ts`.
  </action>
