Create a single migration file with three sections, then apply it via MCP.

**Section 1: Schema columns**

```sql
ALTER TABLE inform.compass_stances
  ADD COLUMN IF NOT EXISTS description TEXT,
  ADD COLUMN IF NOT EXISTS example_perspectives TEXT[] NOT NULL DEFAULT '{}';
```

- description is nullable TEXT (NOT `NOT NULL`) -- the shared inform schema may have rows from other products without authored content. Enforce non-null through seed data, not schema constraint.
- example_perspectives is `TEXT[] NOT NULL DEFAULT '{}'` -- safe because empty array is a valid default for unauthored rows.

**Section 2: Replace RPC function**

```sql
CREATE OR REPLACE FUNCTION connect.get_stances_for_community(p_community_id UUID)
RETURNS TABLE (
  position              INT,
  text                  TEXT,
  supporting_points     TEXT[],
  description           TEXT,
  example_perspectives  TEXT[]
)
LANGUAGE sql
STABLE
SECURITY DEFINER
AS $$
  SELECT
    s.value AS position,
    s.text,
    COALESCE(s.supporting_points, '{}')       AS supporting_points,
    s.description,
    COALESCE(s.example_perspectives, '{}')    AS example_perspectives
  FROM connect.communities c
  JOIN inform.compass_stances s ON s.topic_id = c.topic_id
  WHERE c.id = p_community_id
  ORDER BY s.value ASC;
$$;

GRANT EXECUTE ON FUNCTION connect.get_stances_for_community(UUID) TO anon, authenticated;
```

CRITICAL: Must be `CREATE OR REPLACE FUNCTION` (not `CREATE FUNCTION`). Must include `GRANT EXECUTE` after replacement.

**Section 3: Seed authored content**

UPDATE inform.compass_stances

Content authoring rules (HARD REQUIREMENTS):
1. description: 2-4 sentences describing what this policy stance achieves in practice, written from no partisan perspective. Describe outcomes, not tribal identities.
2. example_perspectives: EXACTLY 3 elements per stance (consistent across all stances for uniform frontend layout). Each element describes who might hold this view in terms of VALUES, GOALS, or LIVED CIRCUMSTANCES -- never party labels.
3. BANNED words/phrases in authored content: "Republican", "Democrat", "conservative", "progressive", "liberal", "left-wing", "right-wing", "left", "right" (when used as political direction), "moderate" (when used as political label). Use values-based framing instead.
4. The stance text from column `text` provides the policy position. The description EXPLAINS it. The example_perspectives describe WHO might hold it and WHY.
5. Read the existing stance `text` from Task 1 carefully -- the description must be consistent with and expand on the existing text, not contradict it.
