<task type="auto">
  <name>Task 2: Create requireAuth, optionalAuth, and requireConnected middleware</name>
  <files>
    src/middleware/auth.ts
    src/middleware/tierGuards.ts
  </files>
  <action>
    1. Create `src/middleware/auth.ts`:
       - Export the `AccountUser` interface with these exact fields:
         - `id: string` (sub claim = Supabase UUID)
         - `tier: 'inform' | 'connected' | 'empowered'`
         - `account_standing: 'active' | 'suspended'`
         - `completed_onboarding: boolean`
         - `display_name: string`
       - Export `requireAuth` async middleware:
         - Extract Bearer token from Authorization header
         - If missing/malformed: return 401 `{ error: 'Missing token' }`
         - Call `jwtVerify(token, JWKS, { issuer: 'https://kxsdzaojfaibhuzmclfq.supabase.co/auth/v1', audience: 'authenticated' })`
         - On JWT failure: return 401 `{ error: 'Invalid token' }`
         - Call `fetch('https://accounts.empowered.vote/api/account/me', { headers: { Authorization: 'Bearer ${token}' } })`
         - If accounts API returns 401: return 401 `{ error: 'Session expired or revoked' }`
         - Parse response as AccountUser, set `user.id = payload.sub`
         - Attach to `req.user`, call `next()`
         - IMPORTANT: Make the accounts API base URL configurable via `process.env.ACCOUNTS_API_URL` (default: `https://accounts.empowered.vote`) for testability
       - Export `optionalAuth` async middleware:
         - If no Authorization header: call `next()` immediately (no error)
         - If header present: delegate to requireAuth
         - If requireAuth fails: call `next()` anyway (swallow error, user stays undefined)
         - IMPORTANT: optionalAuth must NOT send a response on failure — it silently continues

    2. Create `src/middleware/tierGuards.ts`:
       - Export `requireConnected` synchronous middleware:
         - If `req.user` is undefined: return 403 `{ error: 'Connected account required', reason: 'tier' }`
         - If `user.tier` is NOT 'connected' or 'empowered': return 403 `{ error: 'Connected account required', reason: 'tier' }`
         - If `user.account_standing` is NOT 'active': return 403 `{ error: 'Account suspended', reason: 'suspended' }`
         - Otherwise: call `next()`
         - IMPORTANT: Do NOT check completed_onboarding here. connected_no_compass users (completed_onboarding: false) MUST pass this guard. Calibration is NOT a write gate.

    Use proper Express 5 types: `Request`, `Response`, `NextFunction` from 'express'.
    All functions must have explicit return type annotations.
    Use `(SELECT auth.uid())` pattern reminder: this is DB-level only, not relevant to middleware.
  </action>
  <verify>

    - `src/middleware/tierGuards.ts` exports requireConnected
    - Grep for `reason: 'suspended'` in tierGuards.ts confirms distinct suspended error
    - Grep for `completed_onboarding` in tierGuards.ts returns NO results (calibration is not a gate)
  </verify>
  <done>

    - optionalAuth silently passes through when no token is present
    - requireConnected returns 403 with `{ reason: 'suspended' }` for suspended accounts
    - requireConnected returns 403 with `{ reason: 'tier' }` for inform-tier users
    - connected_no_compass users pass requireConnected (no onboarding check)
    - All middleware compiles with strict TypeScript
  </done>
