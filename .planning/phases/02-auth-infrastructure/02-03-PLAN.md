  <name>Task 1: Create AuthContext with token lifecycle and access state detection</name>
  <files>

  <action>
    1. Create `frontend-src/tsconfig.json`:
       - Extends or standalone config for React + TypeScript
       - `compilerOptions`: target ES2022, module ESNext, moduleResolution bundler, jsx react-jsx, strict true, skipLibCheck true
       - `include`: ["**/*.ts", "**/*.tsx"]
       - NOTE: This is a standalone frontend config. The backend tsconfig in the root does NOT cover frontend-src/. The frontend modules will be consumed by Framer's build system in Phase 5.

    2. Create `frontend-src/context/AuthContext.tsx`:
       - Export `AccountUser` interface (same fields as backend: id, tier, account_standing, completed_onboarding, display_name)
       - Export `AccessState` discriminated union type:
         - `{ state: 'loading' }`
         - `{ state: 'inform' }`
         - `{ state: 'connected_no_compass'; user: AccountUser }`
         - `{ state: 'connected'; user: AccountUser }`
       - Export `AuthProvider` component:
         - Uses `useState<AccessState>({ state: 'loading' })` as initial state
         - `useEffect` on mount:
           a. Extract token from URL hash: `new URLSearchParams(window.location.hash.slice(1)).get('access_token')`
           b. If token found: `localStorage.setItem('ev_token', token)` then `window.history.replaceState({}, '', window.location.pathname + window.location.search)` to clean hash — MUST use replaceState, NOT `window.location.hash = ''`
           c. Call `detectUserState()` and set auth state from result
         - `signIn(redirectBack?)`: navigates to `https://accounts.empowered.vote/login?redirect=${encodeURIComponent(redirectBack ?? window.location.href)}`
         - `signOut()`: removes `ev_token` from localStorage, sets state to `{ state: 'inform' }`
         - Provides `{ auth, signIn, signOut }` via context

       - Implement `detectUserState()` async function (can be module-level, not exported):
         - Read token from `localStorage.getItem('ev_token')`
         - If no token: return `{ state: 'inform' }`
         - Fetch `https://accounts.empowered.vote/api/account/me` with Bearer token
         - If 401: remove ev_token from localStorage, return `{ state: 'inform' }`
         - Parse response as AccountUser
         - If `user.tier === 'inform'`: return `{ state: 'inform' }` (edge case: token exists but tier is inform)
         - If `!user.completed_onboarding`: return `{ state: 'connected_no_compass', user }`
         - Otherwise: return `{ state: 'connected', user }`
         - Make the accounts API base URL configurable via an env var (VITE_ACCOUNTS_API_URL) with default `https://accounts.empowered.vote`

       - Export `useAuth()` hook:
         - Reads from AuthContext
         - Throws if used outside AuthProvider

       IMPORTANT: Do NOT expose legal_name or tolerance_rating — only display_name from the accounts API response.
  </action>

    - Grep for `window.location.href =` in signIn confirms redirect (not window.open for signIn — window.open is only for 401 handling in apiFetch)

<task type="auto">
  <name>Task 2: Create typed fetch wrapper and AuthGate component</name>
  <files>
    frontend-src/lib/apiFetch.ts
    frontend-src/components/AuthGate.tsx
  </files>
  <action>
    1. Create `frontend-src/lib/apiFetch.ts`:
       - Export `ApiResult<T>` discriminated union type:
         - `{ ok: true; data: T }`
         - `{ ok: false; error: string; status: number; reason?: string }`
       - Export `apiFetch<T>(path: string, options?: RequestInit): Promise<ApiResult<T>>`:
         - Read API base from `import.meta.env.VITE_API_BASE_URL ?? 'http://localhost:3000'`
         - Read token from `localStorage.getItem('ev_token')`
         - Build headers: `Content-Type: application/json`, plus `Authorization: Bearer ${token}` if token exists
         - Wrap fetch in try/catch for network errors -> return `{ ok: false, error: 'Network error', status: 0 }`
         - On 401 response:
           - Open Auth Hub in a **NEW TAB**: `window.open('https://accounts.empowered.vote/login?redirect=${encodeURIComponent(window.location.href)}', '_blank')`
           - CRITICAL: Must use `window.open(..., '_blank')`, NOT `window.location.href = ...`. This preserves the current tab and any unsaved draft content.
           - Return `{ ok: false, error: 'Session expired - sign in to continue', status: 401 }`
         - On 403 response:
           - Parse body, extract `reason` field if present
           - Return `{ ok: false, error: body.error ?? 'Forbidden', status: 403, reason: body.reason }`
         - On other non-ok responses: return `{ ok: false, error: 'Request failed (${status})', status }`
         - On success: parse JSON, return `{ ok: true, data }`

    2. Create `frontend-src/components/AuthGate.tsx`:
       - Import `useAuth` from AuthContext
       - Export `AuthGate` component that wraps write-action UI (post form, reply form)
       - Props: `children: React.ReactNode` (the active form), `action?: string` (e.g., "reply", "start a thread")
       - Behavior based on auth state:
         - `state === 'loading'`: render a disabled placeholder (skeleton/spinner)
         - `state === 'inform'`:
           - Render a DISABLED (not hidden) form area with an inline message: "Connect your account to {action}"
           - Include a sign-in link that calls `signIn(window.location.href)` to redirect to Auth Hub with current URL as redirect
           - The disabled form should be visually present but non-interactive (disabled textarea, disabled button)
         - `state === 'connected_no_compass'`:
           - Render the children (active form) — connected_no_compass users CAN write
           - Do NOT block or gate based on onboarding status
         - `state === 'connected'`:
           - Render the children (active form)
       - Additionally, export a `SuspendedNotice` component:
         - Renders inline message: "Your account is currently suspended and cannot post."
         - No redirect, no modal — inline notice only
         - Used by parent components when apiFetch returns 403 with `reason === 'suspended'`
         - Suspension reason is NOT exposed (just the fact of suspension)

       IMPORTANT: The AuthGate does NOT handle the suspended state directly (suspension is detected at API call time, not at render time). AuthGate only handles the inform/connected/loading states. SuspendedNotice is a separate component used after a failed write attempt.
  </action>
