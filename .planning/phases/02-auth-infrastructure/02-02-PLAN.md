<task type="auto">
  <name>Task 2: Write auth middleware and tier guard test suites</name>
  <files>
    src/middleware/__tests__/auth.test.ts

  <action>
    1. Create `src/middleware/__tests__/auth.test.ts`:
       Test requireAuth middleware with these cases:
       - **No Authorization header** -> 401 `{ error: 'Missing token' }`
       - **Malformed header** (no "Bearer " prefix) -> 401 `{ error: 'Missing token' }`
       - **Invalid JWT** (random string) -> 401 `{ error: 'Invalid token' }`
       - **Valid JWT but accounts API returns 401** -> 401 `{ error: 'Session expired or revoked' }`
       - **Valid JWT + accounts API returns active connected user** -> req.user is populated with correct fields, response is not 401
       - **Valid JWT + accounts API returns inform tier user** -> req.user is populated (requireAuth does NOT check tier — that's tierGuards' job)

       Test optionalAuth middleware:
       - **No Authorization header** -> next() called, req.user is undefined, no error response sent
       - **Valid JWT + accounts API success** -> req.user is populated
       - **Invalid JWT** -> next() called anyway, req.user undefined (error swallowed)

       **Mock strategy:**
       - If using mock-jwks: Create JWKSMock, start/stop in beforeEach/afterEach. Sign tokens with `jwksMock.token({ sub, aud: 'authenticated', iss: '...' })`.
       - If mock-jwks doesn't work: Use jose `generateKeyPair('ES256')`, `exportJWK`, `SignJWT` to create test tokens. Override JWKS_URL env var to point to a local mock server or use `createLocalJWKSet`.
       - Mock the accounts API fetch using vitest's `vi.fn()` or msw handlers. The fetch to `accounts.empowered.vote/api/account/me` must be interceptable.
       - Use supertest to create test requests against a minimal Express app that mounts the middleware.

       **Test app setup:**
       Create a minimal Express app in the test file (or use createApp from src/app.ts) with a test route:
       ```
       app.get('/test-auth', requireAuth, (req, res) => {
         res.json({ user: req.user });
       });
       ```

    2. Create `src/middleware/__tests__/tierGuards.test.ts`:
       Test requireConnected with mock req objects (no network needed — tierGuards is synchronous):
       - **req.user undefined** -> 403 `{ error: 'Connected account required', reason: 'tier' }`
       - **req.user.tier = 'inform'** -> 403 `{ reason: 'tier' }`
       - **req.user.tier = 'connected', account_standing = 'active'** -> next() called
       - **req.user.tier = 'empowered', account_standing = 'active'** -> next() called
       - **req.user.tier = 'connected', account_standing = 'suspended'** -> 403 `{ reason: 'suspended' }`
       - **req.user.tier = 'connected', completed_onboarding = false, account_standing = 'active'** -> next() called (CRITICAL: calibration is NOT a write gate)

       **Mock strategy:**
       - Use mock Request/Response objects (or supertest with a test route that applies requireConnected after manually setting req.user).
       - tierGuards is pure logic — no network calls, no JWKS. Simple unit tests.

    IMPORTANT: All tests must pass. If mock-jwks has issues, pivot to jose-native testing approach. Do not leave broken tests.
  </action>
