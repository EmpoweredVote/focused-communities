# Milestone v1.0: Launch

**Status:** ✅ SHIPPED 2026-04-17
**Phases:** 1–6 (including inserted Phase 4.5)
**Total Plans:** 23

## Overview

Focused Communities is a civic deliberation platform giving every Empowered Compass topic a dedicated hub with five preset stance positions and an open forum. The build was strictly layered — schema correctness first, auth second, read API third, write API fourth, stance content fifth, frontend sixth, external wiring last — because the RLS policies and memory-over-moderation schema have interdependencies that are cheap to get right and expensive to retrofit.

## Milestone Summary

**Decimal Phases:**
- Phase 4.5: Stance Content Enrichment (inserted after Phase 4) — frontend StanceCard required description + examplePerspectives before rendering; authored 160 rows (32 topics × 5 stances) as a prerequisite to Phase 5

**Key Decisions:**
- New repo (not a section of Civic Spaces) — independent deployment, cleaner Connect Pillar separation
- moderation_status enum (not deleted_at) in all RLS USING clauses — avoids Supabase soft-delete deadlock bug #1941
- Display name snapshotted at post time via DB trigger — pseudonym preserved even after profile name changes
- JWKS singleton + Accounts API dual-check on every write — both required; accounts API call enables session revocation
- Read open / write requires Connected Account — maximizes reach while protecting Connect integrity
- position field stripped at hook boundary (DisplayStance type) — TypeScript enforces no position number ever reaches StanceCard
- Upstash Redis sliding window (5 posts/hour) with in-memory fallback — brigading protection without hard dependency
- Memory over Moderation: posts cannot be deleted; edit history is public; 405 on all DELETE requests
- Cache-Control: private, no-store in requireAuth success path — single location covers all current and future auth-gated routes
- Slug history via pg trigger + array containment fallback — external links (Compass, shares) survive community renames
- 26 communities expanded from initial 5 — one per live Compass topic; stance content pre-seeded for all

**Issues Resolved:**
- Framer + Express auth concern: resolved via Vite/React dev build with VITE_API_BASE_URL for production (Framer deferred to v2+)
- inform.compass_stances cross-schema access: SECURITY DEFINER RPC in connect schema bridges schemas without direct anon grants
- Compass v1.0 spec review: v1.1 changed spoke-tap to LibraryDrawer link (avoids conflicting with calibration overlay UX)
- Taxation community mapped to non-live topic: corrected in community expansion migration
- Token expiry in Accounts PostHistory: EV-Accounts fixed session poll to write fresh token back to store (b3eff0b)

**Issues Deferred:**
- isThreadAuthor uses display_name string match (non-blocking UX; backend ownership check is authoritative)
- ReplyForm maxLength 2000 vs backend 5000 (UI is intentionally more restrictive)
- Compass backend fc_community_slug field: spec delivered, backend team implementing
- Civic Spaces per-topic contextual links: deferred in CIVIC-SPACES-NAV-SPEC.md Section 4
